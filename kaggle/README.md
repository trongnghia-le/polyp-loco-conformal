# Training one LOCO fold on Kaggle

One run = one (fold, seed): train YOLO11 on the 5 source centers, then save every box (conf >= 0.001) on `val`, `cal`, `target`.

## 1. Private dataset (once)
PolypGen images must **never be public** (Synapse terms forbid redistribution).
1. kaggle.com > Datasets > New Dataset. Title e.g. `polypgen-loco`. **Visibility: Private.**
2. Build the upload locally: `python -I scripts/make_kaggle_upload.py` → `outputs/kaggle_upload/polypgen-loco/` (all 8,037 images referenced by the manifest — single frames **and** sequence frames under `sequenceData/` — no masks, plus `manifest.csv`, `splits/fold_C*.csv`, `code/`; ~1.4 GB). The script also writes `outputs/kaggle_upload/polypgen-loco.zip` with forward-slash entry names (do NOT zip with PowerShell: its backslashes are rejected by Kaggle). Upload that zip. Re-run the script and upload a new dataset version whenever the manifest, splits or code change.
3. Resulting layout: `/kaggle/input/polypgen-loco/{manifest.csv, splits/, code/, PolypGen2021_MultiCenterData_v3/data_C1/images_C1/...}`. (Kaggle sometimes inserts an extra folder level; run `!ls /kaggle/input/*` and adjust paths.)

## 2. Notebook settings
New notebook > Add Input > your private dataset. Settings: Accelerator **GPU T4 x2 or P100** (one GPU is used), **Internet on** (pip + the `yolo11*.pt` weights download), Persistence off. Session must be phone-verified for GPU/internet.

## 3. Commands (one cell each)
```
!pip install -q ultralytics==8.4.170
!python /kaggle/input/polypgen-loco/code/train_fold.py --smoke --fold C4 \
   --images-root /kaggle/input/polypgen-loco/PolypGen2021_MultiCenterData_v3 --meta-root /kaggle/input/polypgen-loco
```
Smoke test first (about a minute; checks paths, GPU, parquet). Then the real run:
```
!python /kaggle/input/polypgen-loco/code/train_fold.py --fold C4 --seed 0 --size s --epochs 50 --patience 10 \
   --images-root /kaggle/input/polypgen-loco/PolypGen2021_MultiCenterData_v3 --meta-root /kaggle/input/polypgen-loco
```
(Do not `pip install -r requirements.txt` on Kaggle; Torch/numpy there are preinstalled and a mismatch can break them. If `code/` is not in the dataset, upload the two .py files and call `!python train_fold.py ...`.) Outputs go to `/kaggle/working`. Between the smoke run and the real run, delete `/kaggle/working/*` (`!rm -rf /kaggle/working/*`) so smoke outputs are not mixed in.

Defaults: yolo11s, imgsz 640, AMP, batch 16, 50 epochs, patience 10. Fixed after the first fold, same for all folds/seeds.

## 4. Files to download (Output tab, or "Save Version > Save & Run All (Commit)" then Output)
Into `outputs/kaggle/` locally, one subfolder per run, e.g. `outputs/kaggle/C4_seed0/`:
- `preds_C4_seed0.parquet` (orig_path, role, center, x1, y1, x2, y2, score; original-image pixels; images with no box have no rows, use `index_C4.csv` for the full image list)
- `run_meta.json` (also saved as `run_meta_C4_seed0.json`)
- `index_C4.csv`
- `best_C4_seed0.pt` (about 19 MB; optional, needed for SAM2 stage / re-inference)
- optional: `runs/C4_seed0/results.csv`

A committed notebook keeps its outputs even after the session ends; if you only run interactively, download before the session closes.

## 5. Budget estimate (6 folds x 3 seeds = 18 runs)
From `run_meta.json` of one real run: `seconds.train_total` + `seconds.predict.*` + `seconds.export` = wall-clock per run `T` (fold C4 has 2036 target images; folds differ in size, so scale by number of images: train+val+cal+target counts in `docs/splits.md`). Total GPU hours ~ 18 x T / 3600 (more exactly sum over folds of T_fold x 3). Compare with the weekly GPU quota shown on kaggle.com > your profile > Settings/Account > "GPU" (check the current number there; it changes). Also: one session has a time limit per run (check the current value), so each run must fit in a single session; if one run is too long, lower `--epochs`, use `--size n`, or run seeds in separate sessions. `seconds.epochs` shows per-epoch time; early stopping (`best_epoch`, `epochs_run`) tells how much of the 50-epoch cap is really used.

## 6. All folds: three ready-made notebooks (`kaggle/run_seed0.ipynb`, `run_seed1.ipynb`, `run_seed2.ipynb`)
Generated by `python -I scripts/make_kaggle_notebook.py` (embeds `export_yolo.py` + `train_fold.py`; re-run after editing either). Nothing to edit.
For each: Kaggle > File > Import Notebook, add the private dataset as input, GPU + Internet on, Save Version > Save & Run All (Commit); it runs in the background (6 runs, ~5-6 h). Download `results_seeds_<n>.zip` from the Output tab into `outputs/kaggle/`.
Why three and not one: a Kaggle session has a time limit and 18 runs are ~16 h; the notebooks are independent, so a failure in one never loses the others. Each stops after two consecutive failures and never starts a new run after 8 h. Per-seed results are the same for every fold, so the three can be started in any order (Kaggle may allow two GPU sessions at once; check).
